# 文件类型待确认与当前文件自定义名称设计

## 1. 背景与目标

当前系统对合同、订单、发货单、签收/验收单、发票、回款之外的文件，只能保存为不可命名的“其他”。英文或外语 PDF、海运提单等非预设类型还可能在提示层被误解为混装资料包。

本次改造将三个概念彻底分开：

1. **普通且类型明确的文件**：正常 OCR，进入核对字段。
2. **文件类型不确定的文件**：正常 OCR，进入核对字段，由审计师逐页查看后确认类型。
3. **真正的混装资料包**：只有审计师明确确认一份 PDF 内含多张不同单据时，才进入拆包流程。

自定义类型名称只修改当前文件的显示、归档和导出名称，不创建全局类型，也不增加专属字段或改变审计规则。

## 2. 核心业务规则

### 2.1 类型不确定不等于混装

下列情况只能触发“文件类型待确认”，不得自动触发混装：

- 英文或其他外语文件；
- 海运提单等预设枚举之外的单据；
- OCR 已取得内容，但类型分类置信度不足；
- 文件名和正文无法判断类型；
- 单据类型为 `other`。

准确提示统一为：

> 文件类型不确定，疑似内部存在杂乱的文件类型。请进入核对字段，逐页查看并确认本文件的固定类型。

该提示只表达“类型待人工确认”，不宣称文件已经混装。

### 2.2 混装只能由审计师确认

普通上传的 PDF 无论语言、类型和页数，都不自动升级为混装资料包。

只有以下两种人工动作可以进入混装流程：

1. 上传前勾选“存在混装资料包”，通过混装入口上传；
2. 在核对字段逐页查看后，点击“转为混装资料包”。

混装流程负责页面分组、拆分和各单据类型确认；类型待确认流程只负责给整份文件确认一个固定类型。

### 2.3 当前文件自定义名称

核对字段中的类型选择保留现有预设项，并将“其他”改造成可命名状态：

1. 审计师选择“其他”；
2. 页面显示必填输入框“具体类型名称”；
3. 审计师可填写“海运提单”等名称；
4. 保存后，当前文件在单据列表、原件预览标题、字段对照、结论证据和导出材料中显示该名称；
5. 底层 `doc_type` 仍为 `other`；
6. 自定义名称仅绑定当前文件，不加入全局下拉字典，也不影响其他任务或文件。

建议新增文件级字段：

```text
doc_type = "other"
custom_doc_type_name = "海运提单"
doc_type_source = "human"
doc_type_confirmed = true
```

展示名称使用统一函数：

```text
display_doc_type = custom_doc_type_name（非空时）
                   否则使用预设 doc_type 中文名称
```

## 3. 点击与功能流程

### 3.1 普通且类型明确

```text
上传 PDF
→ 加入待处理
→ 点击开始处理
→ OCR 与类型判断
→ 类型明确
→ 进入核对字段
→ 核对并确认本笔字段
```

### 3.2 文件类型待确认

```text
上传 PDF
→ 加入待处理
→ 点击开始处理
→ OCR 已完成，但类型不确定
→ 文件标记“类型待确认”
→ 进入核对字段
→ 逐页查看整份原件
→ 选择预设类型
   或选择“其他”并填写当前文件具体名称
→ 保存当前文件类型
→ 继续核对字段
```

### 3.3 查看后确认真正混装

```text
进入核对字段
→ 逐页查看整份原件
→ 发现内部确有多张不同单据
→ 点击“转为混装资料包”
→ 进入拆包页面
→ 页面分组、拆分、确认类型和业务归属
→ 确认后进入 OCR/字段识别
→ 返回核对字段
```

### 3.4 上传前已知为混装

```text
上传凭证
→ 勾选“存在混装资料包”
→ 使用混装入口上传
→ 进入拆包页面
→ 人工确认页面边界、类型和业务归属
→ OCR
→ 核对字段
```

## 4. 核对字段页面调整

### 4.1 类型确认区

- 类型明确且已确认：显示预设类型名称。
- 类型不确定：显示醒目的“类型待确认”，但不阻断查看原件。
- 选择“其他”后显示“具体类型名称”输入框。
- 未填写具体名称时，不允许确认当前文件类型，并提示“请填写当前文件的具体类型名称”。
- 提供“转为混装资料包”次级按钮；只有审计师点击后才进入拆包。

### 4.2 逐页查看

- 原件预览保留整份 PDF；支持上一页、下一页和页码定位。
- 类型确认针对整份文件生效，不默认拆页。
- 审计师发现多种单据后主动转入混装流程。

### 4.3 字段对照名称

跨单据对照表采用中性且不会误导的字段名称：

- 将通用日期行统一显示为“文件日期”，不得在发票、订单或其他单据上显示为“签收日期”。
- 具体来源仍保留语义：签收/验收单可注明其日期来自签收/验收日期，发票来自开票日期，订单来自订单日期。
- “购方”和“卖方”分别作为两行展示，均可作为名称勾稽和人工核对的参考依据。
- 购方或卖方缺失时显示“—”，不得把一方内容复制到另一方。

## 5. 状态与数据流

### 5.1 文件状态

文件类型相关状态建议明确为：

- `type_confirmed`：已确认预设类型或已填写自定义名称；
- `type_uncertain`：OCR 完成但类型待人工确认；
- `mixed_declared`：审计师已明确声明混装；
- `mixed_confirmed`：混装拆分结果已人工确认。

`type_uncertain` 与 `mixed_declared` 互不推导。系统不得因前者自动写入后者。

### 5.2 保存行为

保存当前文件类型时：

1. 校验当前文件仍存在于任务中；
2. 校验预设类型，或校验 `custom_doc_type_name` 非空；
3. 更新当前文件，不批量修改同名类型的其他文件；
4. 标记 `doc_type_source=human` 和 `doc_type_confirmed=true`；
5. 重算该文件的字段计划和当前业务缺失字段，但不重新调用 OCR；
6. 保留已识别原文、坐标、图片预处理结果和人工字段修改。

### 5.3 导出行为

- 导出底稿、证据索引和文件清单使用 `display_doc_type`。
- 规则引擎仍按底层 `doc_type=other` 处理自定义名称文件。
- 自定义名称不自动参与三单必备单据判断，也不自动满足合同、订单、签收/验收或发票槽位。

## 6. 错误与边界处理

- 自定义名称去除首尾空格，限制合理长度，拒绝空字符串。
- 自定义名称只允许纯文本，不执行其中的 HTML 或脚本内容。
- 文件类型更改后若影响必填字段，页面重新显示缺失字段，但保留已有人工值。
- 转为混装前如当前文件有未保存字段修改，先提示保存或放弃，不能静默丢失。
- 拆包取消时返回原文件的类型待确认状态。
- 英文、外语或非预设类型不能单独成为拆包触发条件。

## 7. 兼容与迁移

- 现有 `doc_type=other` 文件保持原状态，不自动猜测具体名称。
- 审计师再次打开这类文件时显示“类型待确认”，允许填写当前文件名称。
- 旧任务中仅因类型未知产生的混装提示应迁回类型待确认；人工明确声明的混装记录保持不变。
- 迁移不重新 OCR，不改动原始文件和已有字段证据。

## 8. 验收标准

1. 海运提单、英文或外语 PDF 不再因类型未知自动显示为混装。
2. 类型未知文件完成 OCR 后可以直接进入核对字段逐页查看。
3. 选择“其他”后可以填写“海运提单”，且仅当前文件显示该名称。
4. 刷新页面、切换业务和重新打开任务后，自定义名称仍保留。
5. 自定义名称不进入其他文件或新任务的下拉选项。
6. 通用字段对照行显示“文件日期”，不在发票或订单上误显示“签收日期”。
7. 字段对照同时存在“购方”和“卖方”两行，并展示各自真实来源值。
8. 只有人工声明或点击“转为混装资料包”才进入拆包流程。
9. 类型确认或迁移不重新调用 OCR，并保留人工字段修改。
10. 后端测试、前端交互测试、生产构建和关键页面视觉检查全部通过。
