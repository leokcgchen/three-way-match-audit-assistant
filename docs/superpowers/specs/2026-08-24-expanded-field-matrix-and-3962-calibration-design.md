# 核对字段旧矩阵恢复与 3962 抽取校准设计

## 已批准目标

- “核对字段”默认恢复为字段全部横向摊开的跨单据矩阵。
- 新版可解释证据能力继续保留，但不得替代主矩阵；通过矩阵单元格定位原件，通过辅助入口查看判断依据。
- 以业务 3962 的合同、销售订单、签收验收单和发票为校准样本，修复金额单位、编号角色、主体、货品明细及税价口径。

## 展示口径

主矩阵同时展示四类信息，但只有第一类参与三单一致性：

1. 一致性字段：关联订单号、买卖方、税号/地址、货品、型号、数量、价税合计。
2. 可复算字段：未税单价、税率、税额、含税单价和价税合计。
3. 时序字段：合同日、订单日、计划交付日、到货日、验收完成时间、开票时间；只检查顺序，不要求相等。
4. 单据专有字段：合同号、验收单号、发票号、客户编码、承运人、车辆、签字人、银行信息等；不参与跨单据相等判断。

客户编码跨系统不同只产生“需要映射说明”的辅助预警，不直接判定三单匹配失败。

## 实现约束

- 禁止仅凭数值大小猜测“元/万元”；只有原文明确单位时才换算。
- 文档自身编号必须按单据类型落入对应字段，不得用关联订单号覆盖。
- 发票含税/未税金额和单价必须标明税价口径后再复算。
- 缺失值保持缺失，不以 `0` 代替。
- 回归测试使用从原件校对出的最小文本片段与结构化真值，不把用户原始 PDF 复制进仓库。
