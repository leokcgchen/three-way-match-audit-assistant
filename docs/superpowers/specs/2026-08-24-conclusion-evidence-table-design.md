# 结论页证据表设计

## 目标

审计师应先看到可复核的原始字段证据，再阅读系统结论。三单匹配与截止性结论都必须能回溯到“核对字段”表格和原始单据。

## 交互设计

- “核对字段”页面保留现有字段对照表。
- “三单结论”改为只读横向证据表：行是比较字段，列是订单、签收/验收、发票；每个有来源的值都是按钮。
- 一致字段使用绿色状态和“一致”文字；不一致字段使用红色状态和“不一致”文字；缺值或仅供人工判断使用黄色状态和“需复核”文字。
- 点击证据值后切换到“核对字段”，自动打开字段对照模式，并在右侧原件中定位对应文件和字段。
- “截止性”展示控制权转移日、报告期截止日、序时账入账日和偏差天数的证据链；日期值同样可点击回溯。
- 原有自然语言不通过原因保留在证据表下方，作为解释层而非主要证据层。

## 边界

- 本次只改前端展示与跨页定位，不改变三单匹配、截止性计算或后端结论。
- 不进行 Git 提交。

## 验收

- 三单结论出现横向证据表并显示一致性文字状态。
- 截止性出现日期证据表，自然语言原因仍存在。
- 点击可溯源值后进入核对字段，矩阵模式打开并定位对应原件字段。
- 定向组件测试和前端构建通过。

## 方案一修订：经济字段与串联证据分离

- 三单主表只展示正式引擎参与判断的客户名称、价税合计、数量。
- 单据编号、合同编号、订单编号、发票号码和日期移入“来源标识与日期”，不显示一致性状态。
- 编号仍可点击回到核对字段和原始单据；日期的审计判断只在时序或截止性模块进行。
- `SO/HT/PO` 前缀剥离后的同尾号只能作为业务串联线索，不能单独形成自动绑定通过结论。
