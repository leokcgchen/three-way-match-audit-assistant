# 三单匹配中合同可选设计

## 业务口径

- 三单匹配的基础资料为订单、签收/验收（或发货）和发票。
- 合同属于补强证据，不是三单匹配的前置条件；缺少合同或合同编号不得形成缺字段、红灯或流程阻断。
- 合同已上传时，系统继续提取合同编号和关键条款并展示，但只用于辅助核对。
- 截止性时间线按实际存在的单据计算：无合同时使用订单、签收/验收、发票；有合同时才加入合同日期。

## 修改边界

- 后端 01030 必填字段移除订单的 `contractNo`，合同字段不参与 01030 缺字段门禁。
- 通用字段目录把订单的 `contractNo` 从系统必填移到可选字段。
- 前端必填行与后端保持一致；完整展开矩阵仍可展示实际提取到的合同编号。
- 不改变合同条款测试自身对合同的要求，也不改变其他明确要求合同的底稿目标。

## 验收标准

1. 订单、签收/验收、发票字段齐全但没有合同编号时，`missing_required_fields` 不返回 `contractNo`。
2. 总工作台不再显示“缺字段：合同编号”。
3. 核对字段页面不把合同编号作为必填缺口；实际存在的合同编号仍能出现在展开表中。
4. 无合同时，时序规则使用订单日≤签收/验收日≤发票日，不产生“缺合同日”提示。
