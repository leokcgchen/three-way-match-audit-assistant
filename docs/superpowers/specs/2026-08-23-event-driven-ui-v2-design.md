# 抽凭审阅系统 V2：事件驱动 UI 设计规格

状态：用户已批准设计方向与 150–220 主题分层全量树
日期：2026-08-23
实现状态：仅设计，尚未修改业务代码

## 1. 目标

系统通过“工程化预处理＋确定性规则＋AI 精准提取＋事件驱动人工裁决”提升抽凭审阅效率。正常业务自动处理和留痕；只有缺件、低置信度、账载冲突、关系歧义、规则冲突、审计失败、证据缺失或质量抽检命中时才打断审计师。

## 2. 责任边界

- 人工负责混装 PDF 页面定界、连续页合并、归属冲突和最终异常裁决。
- 工程化处理层保存拖放归属、拆分、合并、去空白、页序和撤销历史。
- 确定性规则先使用编号、金额、日期、文件夹、页序和确认映射。
- AI 负责类型、字段、关系和专业判断建议，并返回置信度、证据位置和理由。
- 门禁服务控制识别、测试、裁决和导出，并保存完整审计轨迹。

## 3. 五个前台画面

### 3.1 新建任务

一次设置单位、期间、底稿目标和抽样清单。清单校验通过后，“创建并进入工作台”生成多笔业务仓库。

### 3.2 多业务工作台

默认隐藏自动通过项，一屏展示多笔业务的状态、缺件、事件数和行内上传。唯一主按钮为“处理 N 个异常”；条件动作包括“复制缺件清单”和“查看已通过”。

### 3.3 混装 PDF 资料整理

仅在混装、多页或归属未知时出现。支持页缩略图矩阵、大图滚动、拆分、并入上一单、并入下一单、移除、撤销、整份归属、业务搜索和类型确认。所有保留页面完成定界后，“确认整理并识别”启动正式处理。

### 3.4 异常裁决中心

原件、证据高亮、账载值、单据原始值、AI 建议、置信度、触发原因和影响范围同屏。可接受 AI、人工覆盖、手工录入、补充资料、确认为审计不通过或作为单据问题放行。“确认裁决并处理下一项”保存裁决并局部重跑。

### 3.5 检查与导出

自动汇总缺件、未定界、未裁决和留痕阻断。有阻断时唯一主按钮为“处理 N 个阻断项”；无阻断时切换为“生成并下载底稿”。生成后提供预览和重新下载。

## 4. 后台流水线

1. 文件标准化：文件指纹、重复检测、方向处理、预览生成、原件保护。
2. 确定性业务匹配：编号、金额、日期、主体、文件夹和人工映射。
3. 单据类型识别：规则优先，AI 补充，冲突或低置信度创建事件。
4. 字段提取：保存原始值、标准化值、OCR 坐标和证据区域。
5. 业务关系与审计测试：关系候选、金额数量勾稽、合同、三单和截止测试。
6. 事件路由：无事件自动绿灯，有事件进入待裁决，阻断事件关闭导出。
7. 局部重跑：人工裁决后只失效并重算受影响结果。

## 5. 事件模型

事件类型包括缺件、低置信度、账载不一致、关系歧义、规则冲突、审计测试失败、证据或留痕缺失、质量抽检命中。

事件记录至少包含：事件 ID、业务编号、类型、严重度、状态、触发规则、原件证据、账载值、AI 建议、置信度、模型与提示词版本、创建时间、裁决人、裁决理由、前后值、影响范围和重跑结果。

## 6. 质量控制

- 自动绿灯业务接受风险抽检和随机抽检。
- 抽检错误转化为真实异常，并分类为规则、OCR、AI 或客户资料问题。
- 人工结论作为受控样例沉淀，不自动直接用于训练。
- 核心指标包括人工触达率、裁决时长、抽检错误率、缺件闭环时间和证据可追溯率。

## 7. 当前功能迁移规则

- 工作台保留；上传凭证合并到批量导入和行内上传。
- 拆包分笔改为条件解锁的资料整理。
- 人工核对重构为异常裁决中心。
- 刷新检查删除，门禁自动刷新。
- 生成和下载合并为“生成并下载底稿”。
- 强制重识别、重扫增强、布局设置等低频功能进入“更多”。
- Gate、内部队列和模型路由术语从普通前台隐藏。
- 批量确认正常项不再作为主入口，无事件业务自动通过并留痕。

完整逐项迁移清单见同批交付的 168 主题 MindMaster 导入文件。

## 8. 验收

- 规范文件无事件时无需人工逐笔确认。
- 混装 PDF 可拆分、连续页合并、移除、撤销和确认归属。
- 缩略图和大图区域均能滚动查看全部内容。
- 每个事件说明触发原因、待决事项和影响范围。
- AI 建议具备置信度、页码、高亮证据和理由。
- 人工覆盖保存人员、时间、理由及前后值。
- 裁决后只局部重跑。
- 未关闭阻断、未定界或留痕缺失时禁止导出。
- 自动绿灯支持抽检并可统计假阴性。
- 每个现有主要按钮都有明确迁移结论。
