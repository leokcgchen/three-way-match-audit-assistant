# 抽样业务主键贯通与可解释匹配设计

日期：2026-08-24

## 目标

把抽样清单选出的业务编号贯通到凭证归属、业务分组和序时账匹配。任何凭证都不能因为 OCR 识别出了订单号、发票号或合同号而覆盖抽样业务主键，也不能自动扩充抽样总体。

## 根因

当前抽样清单与序时账使用 `YW-2025-3962` 一类业务编号，但凭证索引仍依赖只支持 `SO25-0281` 一类格式的旧正则。文件名中的 `YW` 主键被丢弃后，系统错误地用 `SO-251209-7214` 等单据内部编号查询以 `YW` 为键的序时账，并在不同单据类型上分别显示错误的“订单号不存在”或含糊的“账未匹配”。同一格式判断还会把抽样总体误判为空，使抽样范围拦截失效。

## 统一主键规则

每份凭证只允许得到一个规范化的 `sample_business_id`，优先级如下：

1. 审计师上传到具体业务行时写入的人工归属；
2. 文件名中与当前抽样清单业务编号唯一、完整匹配的值；
3. OCR 明确标为“业务编号 / 业务 ID / 业务索引号”的字段值；
4. 无法唯一确定时进入异常区，等待审计师处理，不创建新业务。

`orderNo`、`invoiceNo`、`contractNo`、`documentNo` 等属于业务内部勾稽键，只能用于三单关联，不能覆盖 `sample_business_id`，也不能直接作为序时账主键。

## 匹配与分组

- 抽样范围判断、总工作台业务分组、序时账查询共用已解析的 `sample_business_id`。
- 序时账只使用映射后的业务主键列查询该值；禁止把其他凭证的订单号作为全局候选附加到发票。
- 文件名匹配以本次抽样清单的实际值为词典，不再依赖固定 ERP 前缀；同时保留对明显同族清单外编号的异常识别。
- 同一个抽样业务允许挂接多份订单、签收/验收单和发票；这些单据继续在该业务内部参与一对多三单匹配。

## 可解释状态

每份已识别凭证保留：

- `sample_business_id`：最终采用的抽样业务编号；
- `business_index_source`：`manual`、`filename` 或 `ocr_business_field`；
- `business_index_candidates`：参与判断的候选与来源；
- `ledger_query_biz_id`：实际查询序时账的值；
- `ledger_index_column`：序时账映射后的业务主键列；
- `ledger_match_reason`：成功或失败的结构化原因。

上传凭证列表不再出现裸露的“账未匹配”。失败状态应明确展示：

- 凭证索引值及来源；
- 序时账索引列；
- 实际查询值；
- 未找到、未取得主键或候选冲突的具体原因。

## 异常处理

- 清单内唯一匹配：进入对应业务。
- 同时命中多个清单业务：进入异常区，状态为 `AMBIGUOUS`。
- 明确识别到与抽样主键同族、但不在清单内的业务编号：进入异常区，状态为 `OUT_OF_SAMPLE`，推荐删除。
- 没有取得抽样业务编号：进入异常区，状态为 `UNASSIGNED`，允许审计师人工归属或删除。

## 验收标准

1. 当前 33 份 `YW-2025-xxxx_*.pdf` 均按文件名前缀挂到抽样清单中的 10 笔业务。
2. 序时账查询使用 `YW-2025-xxxx`，不再使用 `SO-...` 作为替代主键。
3. `YW-2025-9999` 等非清单材料进入异常区，不新增业务。
4. `SO`、发票号、合同号不再触发错误的抽样范围冲突。
5. 未匹配状态能说明凭证索引、序时账索引列、查询值和失败原因。
6. 旧 `SO25-0281` 流程仍可正常匹配。
7. 不执行任何 Git 写操作。
