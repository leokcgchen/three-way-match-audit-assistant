# 抽样清单自适应主键识别设计

日期：2026-08-24

## 目标

抽样清单不再要求 ERP 表头必须写成“销售订单号”或“订单编号”。系统应自动识别能够唯一索引抽样业务的主键列，并允许 `SO-251218-7365` 等多段编号格式。

## 识别规则

1. 扫描工作表前 12 行，识别最可能的表头行。
2. 对每一列同时计算表头语义分和数据质量分：
   - 第一优先：业务编号、业务 ID、业务索引号、业务流水号、样本编号、审计索引号等业务主键词。
   - 第二优先：销售订单号、采购订单号、订单编号、交易号、参考号、外部编号等可关联业务词。
   - 凭证号、发票号、行号、日期、金额、客户名称等不得仅凭唯一性成为主键。
3. 关键词命中时，列内必须存在足够的非空、可规范化编号值；不再套用只接受 `SO25-0001` 一类格式的旧正则。
4. 未命中关键词时，从高非空率、高唯一率且呈标识符形态的列中推断；连续行号、日期、金额及长描述列排除。
5. 多列同分且无法可靠区分时不静默猜测，错误信息列出候选列及原因；不得再提示用户必须使用某个固定表头。

## 输出与审计轨迹

解析结果增加：

- `primary_key_column`：实际采用的原始列名；
- `primary_key_method`：`keyword` 或 `uniqueness_fallback`；
- `primary_key_confidence`：本次自动选择的置信度；
- `primary_key_candidates`：必要时保留候选及得分。

抽样总体中的 `business_id` 使用选中主键列的规范化值。原工作表的账载日期、金额、客户信息仍按各自词典独立映射。

## 错误处理

- 找到表头但该列无有效值：提示“已识别候选主键列，但没有可用业务索引值”。
- 找不到可靠主键：提示“未能自动确定唯一业务索引列”，并列出识别到的表头及候选原因。
- 不再使用“请确认表头含销售订单号或订单编号”的固定文案。

## 验收

1. 当前文件优先选中“业务编号”，而不是“销售订单号、凭证号、发票号码”。
2. `YW-2025-3986`、`SO-251218-7365` 等多段编号可正常解析。
3. 未知 ERP 表头在唯一性证据充分时可以自动推断。
4. 纯行号、日期、金额、凭证号、发票号不会被唯一性兜底误选。
5. 原 SAP/金蝶测试样本仍可正常导入。
