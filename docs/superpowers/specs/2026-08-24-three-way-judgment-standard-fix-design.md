# 三单匹配判定标准修复设计

## 目标

修复当前业务链被二次筛空、真实数量被 0 覆盖、空履约结果被误判为“部分履约”的问题，并建立三单匹配、履约累计、截止性三个相互独立的审计判断层。

## 判定层级

### 1. 单据捆绑

- 订单、签收/验收或发货、发票角色齐全。
- 至少存在一个跨单据完全相同的业务引用，才能自动确认同一业务。
- SO/HT/PO 仅数字尾号相同只能作为线索，不能自动通过。

### 2. 三单经济字段勾稽

- 正式一致性字段仅包括：客户名称、价税合计、数量。
- 单据编号、订单编号、发票号码只用于业务串联和原件定位，不要求相等。
- 日期只进入单据时序或截止性测试，不进入三单字段一致性。
- 签收单本身不提供金额时，金额维度只勾稽订单与发票，并将签收金额标记为“不适用/未测”，不能制造失败。
- 数量必须使用 OCR 已提取值或有效逐行累计值；履约累计没有有效行时，禁止用 0 覆盖 OCR 数量。
- 多张发票必须逐张确认客户名称和业务引用后再累计；任一发票客户不一致或无法绑定时，不得用总额相等放行。
- 金额累计统一使用同一口径：优先明细含税金额 `totalAmount`；否则使用 `amount + taxAmount`；再无税额证据时才退回 `amount`，并记录金额口径。

### 3. 一对多履约累计

- 当前业务链传入履约引擎前已经完成范围筛选，不再根据缺失的 `business_group_id` 或 `business_ids` 二次筛选。
- 只有存在有效订单行时，履约累计结果才参与判定。
- 没有有效订单行时，履约累计状态为 `NOT_TESTED`，不生成“部分履约”预警，也不改变三单经济字段结论。
- 同一角色的两份文件若业务单据号、关联订单号、业务日期和数量完全相同，视为同一履约事件的重复佐证，只累计一次；保留重复佐证文件清单供审计师追溯。
- 真实存在部分签收、部分开票、超额、重复来源行或无法唯一绑定时，才产生黄灯或红灯。
- 多张发票、多张签收单分别累计数量与金额，累计值再与订单或合格的合同锚点勾稽。

### 4. 合同替代订单的限定规则

- 优先使用订单作为累计锚点。
- 没有订单时，仅当合同唯一、合同具有明确客户、业务编号以及可复算的数量或金额，并且签收/发票均带有同一合同引用时，合同才可作为替代锚点。
- 合同替代订单必须在结果中标记 `CONTRACT_AS_ORDER_ANCHOR`，不得伪装成已取得订单。
- 合同不唯一、缺少经济字段或无法与全部凭证建立同一引用时，进入人工复核。

### 5. 截止性

- 截止性继续根据控制权转移日、报告期截止日和入账日独立判断。
- 截止性失败不能反向修改三单匹配结论。
- 同一业务允许呈现“三单匹配通过、截止性不通过”。
- 多张发票必须逐张执行截止性判断；总体截止性取最严重结果，任一发票跨期即不能被其他发票的正确期间抵销。

## 状态矩阵

| 场景 | 三单匹配 | 履约累计 | 截止性 |
|---|---|---|---|
| 客户、金额、数量一致；履约行完整 | 通过 | 绿色 | 独立判断 |
| 客户、金额一致；数量未提取且无履约行 | 通过但数量未测 | 未测 | 独立判断 |
| 有效履约行显示部分签收或部分开票，资料未声明齐套 | 带预警通过 | 黄色 | 独立判断 |
| 已声明齐套但有效履约行仍不完整 | 待复核 | 红色 | 独立判断 |
| 累计超额、来源行重复计算或无法确认绑定 | 待复核 | 红色或黄色，按风险区分 | 独立判断 |
| 三单通过但跨期确认 | 通过 | 按履约证据 | 不通过 |
| 无订单但唯一合同满足替代锚点强约束 | 通过并披露合同锚定 | 按履约证据 | 独立判断 |
| 多张发票中任一张客户/业务引用异常 | 待复核 | 不得仅按总额放行 | 逐张判断 |

## 当前 SO25-0296 的正确结果

- 单据捆绑：通过。
- 客户名称：一致。
- 价税合计：订单与发票均为 73,066.70；签收金额不适用。
- 数量：订单、签收/验收、发票均为 912。
- 两份验收文件属于同一履约事件的重复佐证，不重复累计。
- 三单匹配：`AUTO_PASS`，界面显示绿色“通过”。
- 截止性：签收/控制权日为 2025-12-27，入账日为 2026-01-09，跨报告期截止日，仍为不通过。

## 实现边界

- 修复当前链到一对多履约引擎的数据范围传递。
- 在空履约结果处增加 `NOT_TESTED` 防护，并禁止零值覆盖。
- 增加同一履约事件的强键去重，不使用模糊相似度。
- 修复决策协调器：只允许有证据的履约异常改变三单决策。
- 增加多发票逐张客户/引用检查、统一金额口径及逐张截止性结果。
- 增加受限的合同替代订单锚点，不允许无条件用合同填补订单缺失。
- 不改变截止性算法、不修改历史原始 OCR 字段、不操作 Git。

## 验收标准

1. 回归测试必须先复现 SO25-0296 式的“已筛选链再次筛空”问题，并在修复后通过。
2. 当前链的数量角色必须恢复为 912 / 912 / 912，不能显示 0 / 0 / 0。
3. 两份相同验收事件只累计一次。
4. 空履约行不得生成“当前资料部分履约”。
5. SO25-0296 三单结论为绿色通过，截止性仍为失败。
6. 既有真实部分履约、超额和无法绑定测试继续通过。
7. 前端全量测试、后端全量测试和生产构建全部通过。
8. 两张及以上发票能够按统一含税口径累计，且任一发票客户或引用异常会阻止自动通过。
9. 多发票截止性逐张计算，总体结果按最严重状态汇总。
10. 无订单场景只有满足唯一合同强约束时才能使用合同锚点，并留下明确披露。
